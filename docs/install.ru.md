# Установка, обновление, удаление

Права администратора нигде не нужны. Программа лежит в вашей папке: на Windows это `%USERPROFILE%\.backupclaude`. В Program Files и в системные папки ничего не пишется.

## Установка

В PowerShell:

```powershell
irm https://github.com/peregoood-ru/BackUpClaude/releases/latest/download/install.ps1 | iex
```

Скрипт скачивает `backupclaude_<версия>_windows_amd64.zip` и `checksums.txt`, сверяет SHA-256 и останавливается, если хэши разные, затем запускает `backupclaude.exe install` (копирует программу в `%USERPROFILE%\.backupclaude\bin` и добавляет эту папку в ваш PATH) и `backupclaude setup`.

Параметры передаются через блок скрипта:

```powershell
& ([scriptblock]::Create((irm https://github.com/peregoood-ru/BackUpClaude/releases/latest/download/install.ps1))) -NoSetup
```

| Параметр | Что значит |
| --- | --- |
| `-Version 0.1.0` | Указанная версия вместо самой новой |
| `-FromFile <zip или exe>` | Поставить из файла на диске, без скачивания |
| `-Sha256 <хэш>` | Ожидаемый хэш `-FromFile` (без него локальный файл не проверяется) |
| `-NoSetup` | Поставить программу и остановиться |
| `-NoPath` | PATH не менять |

Пока репозиторий приватный, скрипту нужен токен GitHub с правом чтения в `BACKUPCLAUDE_GITHUB_TOKEN`; без него он так и скажет. Другой путь: скачать zip вручную и использовать `-FromFile`.

После изменения PATH нужно новое окно терминала, чтобы заработала короткая команда `backupclaude`.

## Мастер

В `backupclaude setup` восемь шагов: проверка компьютера (система, папка данных, хранилище ключей, данные Claude, планировщик), размещение программы, установка restic и rclone, вопросы, запись настроек, пароль и хранилище, задачи по расписанию, предложение навыка и первый снимок. Образец (сокращённо; с `--lang en` по-английски):

```
Шаг 4 из 8: Вопросы
Где хранить локальную копию (вне Яндекс Диска, OneDrive, Google Drive и Dropbox) [D:\ClaudeBackup\repo]:
Внешняя копия сохранит данные, если этот компьютер потеряют, украдут или он сгорит. Подойдёт любой remote rclone ...
Внешняя копия: rclone:remote:папка, sftp:user@host:/path, папка или Enter, чтобы пропустить:
  [внимание] Внешней копии нет: если компьютер потеряется, украдут или он сгорит, копии пропадут вместе с ним
Куда присылать сообщения о сбоях?
  1. Никуда (смотреть status самому)
  2. Бот Telegram
  3. Адрес webhook
Ваш выбор [1]:
```

У каждого вопроса есть ответ по умолчанию. Локальная копия предлагается на самом просторном диске, который не системный. Папку внутри Яндекс Диска, OneDrive, Google Drive или Dropbox мастер не принимает и объясняет почему, так же как и папку, в которой лежат другие файлы.

В конце мастер объясняет, как записать пароль на бумагу. В терминале он может показать пароль после набранного `yes`, в скрипте не показывает никогда и отсылает к `backupclaude password --show`.

### Повторный запуск

`setup` можно запускать сколько угодно раз. Он сначала читает настройки и меняет только то, что вы ответили:

- `config.json` переписывается только если ответ его меняет, иначе остаётся байт в байт.
- Пароль и хранилище никогда не заменяются.
- Задача планировщика, которая совпадает с настройками, не трогается; отсутствующая или другая ставится заново.
- Если задачи уже запускают программу из какой-то папки, они продолжают её запускать. Флаг `--install` переносит их в `%USERPROFILE%\.backupclaude\bin`.
- В хранилище, где уже есть снимки, новый снимок не делается, пока не указан `--snapshot`.
- Файл настроек, который не читается, не перезаписывается никогда.

### Что сохранять

Мастер спрашивает: **1. Только данные Claude** (по умолчанию) или **2. Данные Claude и папки проектов**. Данные Claude это сессии, чаты, контекст и настройки. Папки проектов это рабочие папки из транскриптов и папки, которые вы добавили в `sources.extra`; если проекты и так лежат в синхронизируемом или резервируемом месте, их можно не сохранять. Тот же выбор есть в `config.json`:

```json
"profiles": { "claude": true, "projects": false }
```

и на вкладке **Настройки** страницы `backupclaude ui`. У выключенного профиля нет задачи в планировщике, `backup` его пропускает, а `status` не считает его отставшим. Снимки, сделанные раньше, остаются и восстанавливаются; программа сама их не удаляет. Если они больше не нужны, удалите их вручную через restic: `restic forget --tag projects --prune` с репозиторием и `--password-command` программы. В `config.json` без `profiles` оба профиля включены. После правки файла выполните `backupclaude schedule install`, чтобы задачи совпали с настройками.

### Без вопросов

`backupclaude setup --yes` берёт все ответы по умолчанию. У ответов есть флаги: `--local`, `--offsite` / `--no-offsite`, `--telegram-chat-id` вместе с `--telegram-token-stdin`, `--webhook-url-stdin`, `--no-notify`, `--skill` / `--no-skill`, `--install` / `--no-install`, `--save claude|all|projects`, `--projects-now`, `--no-snapshot`. С `--json` ответ один объект с шагами, секретов в нём нет. Токен читается из первой строки ввода, а не из аргумента.

## Навык /backup для Claude Code

Его предлагает мастер; можно и командами `backupclaude skill install` и `backupclaude skill remove`. Навык это один файл, `~/.claude/skills/backup/SKILL.md`. Он говорит Claude вызывать `status`, `list` и `restore` с `--json`, сначала восстанавливать в отдельную папку, возвращать файлы на место (`--apply`) только после вашего согласия и никогда не запускать `password --show`. Навык с таким же именем, который написала не эта программа, не трогается.

В Claude Code введите `/backup` или просто попросите: «верни сессию, которую я вчера удалил».

## Обновление

```
backupclaude update --check     только посмотреть
backupclaude update             скачать, проверить, заменить
```

Программа ищет самый новый опубликованный выпуск, скачивает архив для вашей системы и `checksums.txt` и останавливается, если SHA-256 не совпал. Новый файл она запускает, чтобы убедиться, что он работает, и затем подменяет старый. Работающий `.exe` на Windows нельзя перезаписать, но можно переименовать, поэтому старый файл становится `backupclaude.exe.old` и удаляется при следующем запуске. Настройки, расписание и копии не затрагиваются, задачи продолжают указывать на тот же файл. Если новая версия закрепляет другие версии restic и rclone, она их скачивает.

Для приватного репозитория задайте `BACKUPCLAUDE_GITHUB_TOKEN`; без него команда скажет, что репозиторий приватный и что делать. `backupclaude update --from-file <zip или exe> [--sha256 <хэш>]` ставит файл, который вы скачали сами.

## Удаление

```
backupclaude uninstall          сначала спросит
backupclaude uninstall --yes    не спрашивает
```

Убирает задачи Планировщика, restic и rclone, кэш, навык `/backup` (только если его написала эта программа), саму программу и её папку из PATH. **Не трогает:**

- локальные копии и внешнюю копию;
- пароль в хранилище ключей (диспетчер учётных данных, запись `BackUpClaude:repository-password`). Прежде чем делать что-то ещё, убедитесь, что пароль записан на бумагу;
- настройки и журналы в `%USERPROFILE%\.backupclaude`, чтобы следующий `setup` их подхватил. `--purge` удаляет и их, вместе с токеном бота и адресом webhook в хранилище ключей. `rclone.conf`, где может лежать вход во внешнее хранилище, остаётся всегда.

Работающая программа не может удалить себя на Windows: скрытый помощник удаляет файл через несколько секунд после конца команды.

## Попробовать на компьютере, где уже есть копии

`BACKUPCLAUDE_SANDBOX=имя` (буквы и цифры) даёт папке задач в планировщике, группе в хранилище ключей и ключу PATH собственное имя, так что проба не коснётся настоящих. Вместе с другими `BACKUPCLAUDE_HOME` и `USERPROFILE` это вторая, отдельная установка. Всю цепочку так проходит `scripts/e2e-windows.ps1 -Exe backupclaude.exe -Sandbox имя`.

## Если что-то не так

- *«Папка ... лежит внутри Яндекс Диска»*: выберите папку вне синхронизируемых, например на другом диске.
- *«Нет доступа к выпускам»*: репозиторий приватный; см. раздел про обновление.
- *Windows защитила ваш компьютер*: программа не подписана; см. README.
- *Команда `backupclaude` не найдена*: откройте новый терминал или запустите программу по полному пути `%USERPROFILE%\.backupclaude\bin\backupclaude.exe`.
- `backupclaude doctor` находит большинство остальных проблем и говорит, что делать.
