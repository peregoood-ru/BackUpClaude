# Восстановление

[English](restore.md)

Здесь три ситуации: пропала сессия, испорчен проект, компьютер умер и стоит новая Windows. Команды одинаковые, отличается только то, что вы возвращаете.

## Как это устроено

- **Сначала всегда в отдельную папку.** `backupclaude restore` кладёт файлы в новую папку рядом с локальным хранилищем, например `D:\ClaudeBackup\restored\2026-11-03_195814`. На месте при этом ничего не меняется. Внутри папки повторяется исходный путь: `C\Users\Имя\.claude\projects\...`.
- **Каждый файл проверяется.** restic перечитывает каждый восстановленный файл и сверяет его с копией. В конце команда печатает хэш всего восстановленного дерева.
- **`--apply` только добавляет.** С этим ключом недостающие файлы возвращаются туда, где были. Существующий файл не заменяется никогда, даже если он отличается от копии. Его версия из копии остаётся в папке восстановления.
- **`--dry-run` вместе с `--apply`** показывает список того, что вернётся, и ничего не пишет.
- **Базы приложения не смешиваются.** Local Storage и IndexedDB приложения Claude возвращаются только целиком и только при закрытом Claude. Пока Claude запущен, команда откажет и ничего не изменит.
- **Без флагов команда задаёт вопросы.** Запустите `backupclaude restore` в терминале: она спросит, что и куда вернуть, и покажет последние сессии. Сессии, которых уже нет на диске, помечены «только в копии».
- **Внешняя копия.** По умолчанию восстановление идёт из локальной копии. Внешнюю выбирает ключ `--from offsite`. Если внешняя копия ещё не настроена, команда так и скажет.

`backupclaude restore --help` показывает все ключи.

## 1. Пропала сессия

Признак: сессии нет в списке Claude Code (`claude --resume`) или в приложении.

1. Найдите id сессии.

   ```
   backupclaude list --sessions
   ```

   Сессия, которой нет на диске, помечена «только в копии». Можно и не искать: `backupclaude restore` без флагов покажет последние сессии с номерами.

2. Посмотрите, что вернётся. На месте при этом ничего не меняется.

   ```
   backupclaude restore --session 0fc6092b
   ```

   Хватает первых 8 символов id. Если сессии нет в последнем снимке, команда сама найдёт её в более старом. Конкретный снимок выбирает `--snapshot <id>`, а список снимков даёт `backupclaude list --snapshots`.

3. Верните сессию на место.

   ```
   backupclaude restore --session 0fc6092b --apply
   ```

   Вернутся транскрипт, папка сессии (субагенты, вывод инструментов) и история правок файлов. Всё, что уже есть на диске, останется как было.

4. Откройте сессию. Команда сама напечатает, из какой папки её открыть:

   ```
   cd "D:\Проекты\сайт"
   claude --resume 0fc6092b-f4d7-460e-ab01-acc244289ebe
   ```

   **Сессия из приложения Claude** (Desktop или Cowork) возвращается вместе со своим описанием и с транскриптом Claude Code, на который оно ссылается. Приложение держит список сессий в памяти, поэтому закройте Claude полностью, включая значок у часов, и запустите снова.

## 2. Испорчен проект

Признак: файлы проекта удалены или испорчены, например неудачной правкой, синхронизацией или вирусом.

1. **Ничего не делайте с испорченной папкой**, пока не восстановите копию.

2. Выберите снимок до порчи. Проекты сохраняются раз в сутки.

   ```
   backupclaude list --snapshots
   ```

3. Восстановите проект в отдельную папку и сравните её с испорченной.

   ```
   backupclaude restore --project сайт --snapshot 0a83c76c
   ```

   В `--project` подходит имя папки проекта, часть имени или полный путь. Без `--snapshot` берётся последний снимок. Нужные файлы можно перенести из папки восстановления вручную.

4. Или верните на место только пропавшие файлы.

   ```
   backupclaude restore --project сайт --snapshot 0a83c76c --apply --dry-run
   backupclaude restore --project сайт --snapshot 0a83c76c --apply
   ```

   Изменённые файлы `--apply` не заменяет. Команда скажет, сколько их и что они отличаются от копии. Если нужен проект ровно как в снимке, переименуйте испорченную папку, например в `сайт-испорчено`, и выполните команду с `--apply`: проект вернётся целиком.

   Чтобы вернуть проект в другое место, добавьте `--map "СТАРЫЙ_ПУТЬ=НОВЫЙ_ПУТЬ"`.

## 3. Компьютер умер, стоит новая Windows

У вас есть только пароль на бумаге и доступ к внешнему хранилищу. Подойдёт и локальная копия, если уцелел её диск. Имя пользователя и буквы дисков на новом компьютере могут быть другими.

1. **Скачайте `backupclaude.exe`** и положите в любую папку, например `C:\Tools`. Права администратора не нужны. restic скачается сам при первом восстановлении, его хэш сверяется с закреплённым в программе.

2. **Подготовьте доступ к копии.**
   - Копия на диске (USB, NAS, уцелевший диск): нужен только путь к папке хранилища, например `E:\ClaudeBackup\repo`.
   - Копия во внешнем хранилище через rclone, например Яндекс Диск: адрес вида `rclone:yandex:BackUpClaude`. Нужны и настройки входа rclone в файле `%USERPROFILE%\.backupclaude\rclone.conf`. Как подключить хранилище, будет описано в `docs/storage.ru.md` вместе с внешней копией.

3. **Восстановите всё в отдельную папку.**

   ```
   C:\Tools\backupclaude.exe restore --repo E:\ClaudeBackup\repo --all
   ```

   Команда попросит пароль. Введите его с бумаги: при вводе символы не показываются. Пароль никуда не записывается. Восстановятся последние снимки данных Claude и проектов. Папка восстановления появится рядом с хранилищем, а для адреса rclone в `%USERPROFILE%\BackUpClaude\restored`.

4. **Поставьте Claude.** Установите Claude Code и приложение Claude, войдите в аккаунт. Файл входа `.credentials.json` в копию не попадает, поэтому войти нужно заново. Запустите приложение один раз и закройте его полностью, включая значок у часов.

5. **Посмотрите, куда что вернётся.**

   ```
   C:\Tools\backupclaude.exe restore --repo E:\ClaudeBackup\repo --all --apply --dry-run
   ```

   Строки «путь … станет …» показывают перенос: старая домашняя папка становится новой, папка старого приложения становится папкой приложения на этом компьютере. Если проекты лежали на диске, которого здесь нет (например, `D:`), команда об этом скажет. Укажите новое место:

   ```
   ... --map "D:\YandexDisk=E:\YandexDisk"
   ```

6. **Верните файлы на место.** Это та же команда без `--dry-run`. Папки транскриптов переименуются под новые пути проектов, а пути внутри настроек Claude (`.claude.json`, описания сессий) заменятся. Транскрипты и файлы проектов копируются без изменений.

   Local Storage и IndexedDB свежеустановленного приложения уже существуют, поэтому старые базы не возвращаются: базы не смешиваются. Чтобы взять старые, закройте Claude, переименуйте эти папки (их путь напечатан) и повторите команду. Боковая панель приложения тогда станет как раньше.

7. **Откройте сессию** командой `claude --resume <id>` из папки проекта, как в ситуации 1.

8. **Снова включите бэкап.** Мастер `backupclaude setup` (появится в версии 0.1.0) подключит ту же копию, чтобы история продолжилась.

## Если что-то пошло не так

| Сообщение | Что делать |
| --- | --- |
| «Этот пароль не открывает хранилище» | Сверьте пароль с бумагой: группы по 4 символа через дефис, букв I, L, O, U в нём нет. Проверьте, та ли это копия. |
| «Внешняя копия ещё не настроена» | Восстанавливайте из локальной (`--from local`, так по умолчанию). |
| «Claude запущен…» | Закройте Claude полностью и повторите. Восстановленные файлы уже лежат в папке, путь напечатан. |
| «Не возвращено: … на диске, которого нет» | Добавьте `--map "СТАРЫЙ=НОВЫЙ"`. |
| «Сессии … нет ни в одном снимке» | Сессия моложе последнего почасового снимка ещё не сохранена. Проверьте id в `backupclaude list --sessions`. |

## Пробное восстановление

Раз в четыре недели, в воскресенье в 08:00, задача `restore-test` проверяет, что копии читаются. Она проверяет десятую часть данных командой `restic check --read-data-subset 10%`. Затем восстанавливает до 60 случайных файлов последних снимков в пустую папку рядом с хранилищем и сверяет SHA-256 каждого с оригиналом на диске, после чего удаляет папку. О сбое сообщение приходит сразу. Успех виден в `backupclaude status` и в недельной сводке. Запустить проверку вручную: `backupclaude run --job restore-test`.

`restic mount` не используется: в restic 0.19.1 для Windows этой команды нет.
